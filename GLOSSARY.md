# Algo Visualizer

Учебный проект: Go-библиотека алгоритмов (`algorithms/`) + веб-визуализатор (`visual/`) + CLI-опросник (`quiz/`). Программа обучения — три блока: фундамент, деревья, графы+ДП.

## Language

### Общие термины проекта

**Algorithm**:
Чистая функция или структура данных в `algorithms/`, не знающая о UI. Может работать в «тихом» режиме (просто считает результат) или с эмиттером событий.
_Avoid_:implementation, функция

**Emitter**:
Единый интерфейс, в который алгоритм «стреляет» типизированными событиями во время работы. В тихом режиме не используется (nil-эмиттер).
_Avoid_: recorder, callback (callback — конкретный вид эмиттера)

**Event / Step**:
Типизированное событие, описывающее один атомарный шаг алгоритма (сравнение, обмен, визит вершины). Алгоритм определяет свои типы событий; протокол/emitter — общий.
_Avoid_: log, trace (они подразумевают текстовые логи)

**Quiet mode**:
Работа алгоритма без эмиттера — как обычная библиотечная функция. Основной режим для тестов и переиспользования.
_Avoid_: silent mode, no-ops mode

**Module (учебный модуль)**:
Единица учебной программы: одна тема или связная группа тем. Завершённый модуль включает все применимые части (реализацию, тесты, визуализацию, вопросы квиза); он может быть разбит на несколько тикетов и рабочих сессий. Одна строка в `PROGRESS.md` соответствует одному модулю.
_Avoid_: ticket, задача

**Ticket (тикет)**:
Вертикальный срез реализации с проверяемым результатом; один worktree и одна ветка соответствуют одному тикету. Несколько тикетов могут вместе завершать учебный модуль.
_Avoid_: module, учебный модуль

**Block (блок программы)**:
Группа модулей: Блок 1 «Фундамент», Блок 2 «Деревья», Блок 3 «Графы + ДП».
_Avoid_: chapter, раздел

**Hash Table (хеш-таблица)**:
Структура для хранения пар «ключ — значение», которая выбирает корзину по результату хеш-функции.
_Avoid_: map (кроме имени типа Go), ассоциативный массив

**Bucket (корзина)**:
Позиция в массиве хеш-таблицы, в которую хеш-функция направляет ключ; при методе цепочек корзина может содержать несколько записей.
_Avoid_: слот

**Collision (коллизия)**:
Ситуация, когда разные ключи отображаются в одну корзину.
_Avoid_: конфликт (слишком общее)

**Separate Chaining (метод цепочек)**:
Способ разрешения коллизий, при котором записи одной корзины хранятся в связанной последовательности.
_Avoid_: открытая адресация

**Bubble Sort (сортировка пузырьком)**:
Сравнивает соседние элементы и меняет местами пару, если она расположена не по порядку; повторяет проходы, пока массив не отсортирован.
_Avoid_: сортировка пузырьков

**Selection Sort (сортировка выбором)**:
На каждом проходе находит минимум неотсортированной части и помещает его в её начало; стандартный вариант может менять относительный порядок равных элементов.
_Avoid_: выборочная сортировка

**Insertion Sort (сортировка вставками)**:
Поддерживает отсортированный префикс и вставляет в него очередной элемент, сдвигая большие значения; при сдвиге только строго больших элементов сортировка устойчива.
_Avoid_: вставочная сортировка

**Insertion Gap (дырка вставки)**:
Временно свободная позиция в отсортированном префиксе, в которую после сдвига больших значений вправо помещается удерживаемый ключ.

**Merge Sort (сортировка слиянием)**:
Рекурсивно делит диапазон пополам, сортирует половины и сливает их через вспомогательный буфер; при равных значениях первым берётся элемент левой половины, поэтому выбранная top-down реализация устойчива. Память — O(n), время — O(n log n) во всех случаях.

**Quicksort (быстрая сортировка)**:
In-place сортировка по возрастанию: рекурсивно разбивает диапазон partition вокруг pivot, затем сортирует части по обе стороны от него. В проекте выбран вариант Lomuto (pivot — последний элемент диапазона, сразу перед сканированием) со строгим сравнением: равные pivot значения уходят вправо. Вариант неустойчив: дальние обмены при partition (перенос строго меньших на границу блока) и финальное размещение pivot могут перемещать значения через другие равные им значения и тем самым изменить взаимный порядок равных; среднее время O(n log n), худшее — O(n²), в частности на уже упорядоченных входах.

**Pivot (опорный элемент)**:
Значение, относительно которого partition раскладывает диапазон; в выбранном варианте quicksort — последний элемент диапазона, после partition занимающий финальную позицию между частями.
_Avoid_: опора, эталон

**Partition (разбиение)**:
Один шаг quicksort: раскладка значений диапазона вокруг pivot — строго меньшие собираются в левую часть, не меньшие остаются в правой — и помещение pivot на финальную позицию. Границы диапазона включительные с обеих сторон (lo..hi).
_Avoid_: разделение, split (в проекте split обозначает не только расщепление узла B-дерева, но и входит в имя события MergeSplit — деления диапазона пополам в merge sort; шагу quicksort соответствует только «разбиение»)

**Stable Sort (устойчивая сортировка)**:
Сортировка, сохраняющая исходный относительный порядок элементов с равными ключами.

**In-place Sort (сортировка на месте)**:
Сортировка, которая переупорядочивает переданную коллекцию без создания дополнительной коллекции размера, пропорционального входу.

**Binary Tree (бинарное дерево)**:
Дерево, в котором у каждого узла есть не более двух потомков, различаемых как левый и правый. Бинарное дерево не обязательно является BST; значения узлов могут повторяться.
_Avoid_: BST (это более узкое понятие)

**Tree Node (узел дерева)**:
Элемент дерева со значением и связями с потомками; два узла могут иметь одинаковое значение, оставаясь разными узлами.

**NodeID (идентификатор узла)**:
Стабильное имя узла — его путь от корня символами L/R (корень — root). Идентичность узла не выводится из значения: два узла с одинаковым значением остаются разными узлами. Это контракт бинарных деревьев (`kind="tree"`: обходы, BST); Trie-кадры используют отдельный термин — Trie Node ID.
_Avoid_: node value (значение — атрибут узла, не его идентичность), индекс, ключ

**Trie Node ID (идентификатор узла Trie)**:
Frame-local идентификатор узла в снимке `kind="trie"` — путь от корня по rune-меткам рёбер в каноническом кодировании: `root` для корня, далее по одному сегменту на rune — `U+` плюс шестнадцатеричный код rune в верхнем регистре минимальной ширины 4 (длиннее при необходимости), разделитель `/` (например, `root/U+043F/U+0440`). Идентификатор уникален в пределах снимка; межкадровая стабильность не обещается. Это отдельный контракт Trie-кадров, не переиспользующий бинарный NodeID с символами L/R.
_Avoid_: NodeID (это контракт бинарных деревьев), значение узла (идентичность определяется путём, а не меткой ребра как значением узла)

**Tree Traversal (обход дерева)**:
Систематическое посещение узлов дерева в определённом порядке.
_Avoid_: обход графа (у графа иные условия, например возможны циклы)

**In-order Traversal (симметричный обход)**:
Обход бинарного дерева, посещающий левое поддерево, текущий узел, затем правое поддерево.

**Pre-order Traversal (прямой обход)**:
Обход бинарного дерева, посещающий текущий узел, затем левое и правое поддеревья.

**Post-order Traversal (обратный обход)**:
Обход бинарного дерева, посещающий левое и правое поддеревья, затем текущий узел.

**Level-order Traversal (обход по уровням)**:
Обход бинарного дерева, посещающий узлы по уровням сверху вниз и слева направо внутри уровня; обычно поддерживает очередь.

**BST (бинарное дерево поиска)**:
Бинарное дерево со строгим порядком: все значения левого поддерева узла меньше его значения, правого — строго больше. Значение узла и есть ключ; ключи уникальны, повторная вставка существующего ключа не меняет дерево. Операции — O(h); у перекошенного дерева h = n.
_Avoid_: бинарное дерево (без «поиска» — более общее понятие)

**Inorder Successor (inorder-преемник)**:
Узел со следующим по величине ключом после данного. При удалении узла BST с двумя потомками — минимум правого поддерева: он больше удаляемого узла и меньше всех остальных узлов поддерева. В текущей реализации значение преемника переносится в удаляемый узел, а сам преемник затем вырезается рекурсивным remove от корня правого поддерева: спуск заново идёт по левому пути до преемника, у которого нет левого потомка.
_Avoid_: следующий узел (не определено, в каком порядке), следующий элемент (термин списков и массивов)

**Rotation (поворот дерева)**:
Локальная перестройка ссылок вокруг пары «узел — потомок», меняющая форму дерева, но не порядок: **левый поворот** поднимает правого потомка на место узла, **правый поворот** — левого; одно из поддеревьев поднимавшегося потомка переходит опустившемуся узлу. Значения узлов не меняются, inorder-порядок и BST-инвариант сохраняются, поэтому повороты — базовый инструмент самобалансирующихся деревьев; двойной поворот — композиция двух одиночных. В текущей библиотеке BST повороты не реализованы — тема концептуальная.
_Avoid_: перестановка значений (поворот меняет ссылки, а не значения), ребалансировка (общий процесс поддержания высоты, а не один поворот)

**B-Tree (B-дерево)**:
Сбалансированное дерево поиска, в котором узел хранит несколько упорядоченных ключей — разделителей диапазонов. Внутренний узел с `k` ключами имеет `k + 1` потомок; у листа потомков нет. Все листья лежат на одной глубине; высота растёт только при расщеплении (split) корня. Небольшая высота за счёт высокого ветвления узла (branching factor) делает структуру подходящей для страничного хранения: чтений страниц по пути поиска — по числу уровней дерева. В библиотеке не реализовано — концептуальная тема.
_Avoid_: BST (в узле BST один ключ и не более двух потомков), бинарное дерево (общее понятие: не более двух потомков у узла)

**Split (расщепление узла B-дерева)**:
Реакция вставки на узел, заполненный по выбранной конвенции: узел делится на два узла поменьше, ключ-разделитель из середины продвигается вверх — в родительский узел; при переполнении корня продвинутый ключ становится новым корнем, и высота растёт на 1. Слово «разбиение» в проекте означает шаг quicksort (partition), поэтому для операции B-дерева используется «расщепление» (split). Это не единственное употребление слова split в проекте: в merge sort есть событие MergeSplit — деление диапазона пополам, отдельная операция.
_Avoid_: разделение узла, разбиение узла («разбиение» занято шагом quicksort — partition)

**Branching Factor (ветвление узла)**:
Число потомков узла. В B-дереве у внутреннего узла с `k` ключами ветвление равно `k + 1` (у листа — 0); чем выше ветвление, тем ниже дерево при том же числе ключей и тем меньше чтений страниц по пути поиска. В бинарном дереве ветвление узла ограничено двумя.
_Avoid_: арность, степень узла

**KD-Tree (KD-дерево)**:
Дерево для хранения точек в k-мерном пространстве: каждый узел хранит точку, а внутренний узел (узел с потомками) вдобавок делит свою область плоскостью по одной выбранной координате — координате-разделителю: точки с меньшим её значением уходят в левое поддерево, с большим — в правое. Лист — узел без потомков — область не делит: сохранённые координаты его точки сами по себе разделяющими не становятся. Выбор координаты-разделителя — часть конвенции реализации (типичный пример — цикл по осям по глубине, а не обязательное свойство всех вариантов). Поиск ближайшего соседа использует отсечение областей, которые не могут улучшить текущий лучший результат; отсечение зависит от данных и формы дерева и не даёт гарантированной O(log n) — худший случай может потребовать осмотреть все точки. В библиотеке не реализовано — концептуальная тема.
_Avoid_: BST (разбиение по координатам, а не сравнение ключей), дерево поиска (спуск по координате задаёт только область, не порядок ключей)

**DOM (Document Object Model, объектная модель документа)**:
Дерево объектов документа, которое строит парсер из исходного текста: элементам и тексту соответствуют узлы-объекты, связанные отношением «родитель — потомок», а атрибуты принадлежат элементу — объект-атрибут тоже реализует интерфейс узла, но родителя и потомков в дереве у него нет. Отражает структуру документа, а не его точную запись: пробелы и переносы, как правило, хранятся в узлах текста (HTML нормализует концы строк к LF; отдельные контексты разбора могут обрабатывать пробелы по своим правилам), а детали записи HTML — например, регистр имени тега, кавычки вокруг значения атрибута и написание символьных ссылок — в дереве не сохраняются. В библиотеке не реализовано — концептуальная тема.
_Avoid_: HTML-файл (DOM — не сам текст), AST (другая предметная область — синтаксис программы), потомок-атрибут (атрибут не является потомком в дереве документа)

**AST (Abstract Syntax Tree, абстрактное синтаксическое дерево)**:
Дерево синтаксических конструкций программы: узлы — операции, вызовы, объявления, потомки — их составные части; приоритет и вложенность выражаются формой дерева. Абстрагируется от части деталей исходной записи (скобок, части разделителей, комментариев). В библиотеке не реализовано — концептуальная тема.
_Avoid_: DOM (дерево документа, не программы), дерево символов (узлы — конструкции, а не символы записи)

**Rune (руна)**:
Для Trie одна руна — одно Unicode scalar value (см. Unicode Scalar Value): не UTF-8 байт и не UTF-16 code unit. Supplementary-символ (например, `😀`, U+1F600) — одна руна: слова разбиваются на руны при переходах по дереву, события посещения/проверки считаются по рунам, лимиты длины слова/префикса — в рунах, идентификаторы узлов строятся из hex-кодов руны.
_Avoid_: байт (переходы и события не по UTF-8 байтам), code unit (JS-строки — UTF-16, но счёт по рунам), знак/символ (разговорное, не единица контракта), code point (в качестве синонима руны)

**Unicode Scalar Value (скалярное значение Unicode)**:
Валидная кодовая позиция Unicode вне диапазона surrogate (U+D800–U+DFFF); понятие code point шире — оно включает surrogate values, которые scalar values не являются.
_Avoid_: code point (как синоним scalar value — не эквивалентны), символ (разговорное)

**Trie (префиксное дерево)**:
Выбранная концепция структуры для хранения строк: классическое несжатое дерево, в котором от корня идут переходы по отдельным Unicode rune, путь от корня до узла кодирует начало слова, а узел с отметкой конца слова — само слово. Общие префиксы слов разделяются и переиспользуются. Операции — O(m), где m — длина слова/префикса. Пустое слово не хранится; Insert и Delete от пустого слова отвергаются ошибкой. На инициализированном Trie (`NewTrie()`) пустой префикс валиден: StartsWith("") возвращает true даже в пустом Trie, Search("") всегда false. Nil-приёмник и нулевое значение `Trie{}` — неинициализированный Trie, а не пустой инициализированный: операции с ошибочным результатом отклоняются ошибкой `ErrUninitializedTrie` до любых событий, `Len()` возвращает 0. В проекте выбран несжатый вариант; compressed/radix-варианты вне объёма модуля.
_Avoid_: дерево поиска (ключи не упорядочены сравнением «больше/меньше»), radix tree (сжатый вариант, вне объёма)

**Word-End Node (терминальный узел)**:
Узел Trie, помеченный флагом конца слова: путь от корня до него образует сохранённое слово. Терминальный узел не обязан быть листом — он может лежать на пути к более длинным словам (слово-префикс другого слова). Обычный промежуточный узел конца слова не образует.
_Avoid_: лист Trie (терминальный узел не обязан быть листом), терминальный символ (отметка — флаг узла, а не отдельный символ слова)

**Prefix (префикс)**:
Абстрактно — последовательность rune, совпадающая с началом другой последовательности, включая совпадение целиком; пустая строка — префикс любой строки. В Trie префиксу соответствует путь от корня по rune, который может заканчиваться отметкой конца слова или лежать на пути к более длинным словам. StartsWith проверяет существование такого пути в Trie, независимо от того, образует ли путь конец слова; на инициализированном Trie (`NewTrie()`) пустой префикс соответствует корню — путь к корню есть всегда, поэтому StartsWith("") возвращает true, в том числе в пустом Trie, где сохранённых слов нет. Неинициализированный Trie (nil-приёмник, нулевое значение `Trie{}`) операции с ошибочным результатом отклоняют ошибкой `ErrUninitializedTrie`.
_Avoid_: подстрока (совпадение не обязано начинаться с начала слова)

**Pruning (pruning при удалении)**:
Очистка Trie после удаления слова: стираются только узлы, которые больше не ведут ни к какому концу слова; ветвления и узлы на путях к другим словам (включая сохранённые слова-префиксы) остаются.
_Avoid_: удаление поддерева целиком (грубая очистка ломает общие префиксы)

### Графы

Термины темы «Основы графов». Записи описывают выбранную концепцию модуля и не утверждают состояние реализации; точные сигнатуры и формы результатов следуют пользовательским черновикам библиотечных тикетов.

**Graph (граф)**:
Множество вершин и рёбер между ними. В модуле «Основы графов» графы невзвешенные; вершины — целые ID `0..n-1`; поддерживаются режимы directed и undirected; изолированные вершины и несвязные графы валидны. Параллельные и дублирующие рёбра отклоняются ошибкой; петля разрешена.
_Avoid_: сеть, мультиграф (параллельные рёбра вне объёма), взвешенный граф (вне объёма модуля)

**Directed / Undirected Graph (ориентированный / неориентированный граф)**:
Два режима графа: в directed рёбра имеют направление — путь обязан идти по стрелке; в undirected ребро проходимо в обе стороны. Режим выбирается при задании графа и влияет на обходы и условия цикла.
_Avoid_: «стрелочный/обычный граф», digraph как единственный термин

**Adjacency List (список смежности)**:
Представление графа, в котором для каждой вершины хранится список её соседей; память O(V+E), перечисление соседей вершины — O(deg). В проекте соседи перечисляются в порядке возрастания номеров вершин — перебор соседей делает обходы детерминированными; порядок посещения в выходах DFS/BFS остаётся фактическим порядком обхода, а не сортировкой по возрастанию. Поверх списка смежности реализуются DFS, BFS и поиск циклов; для матрицы алгоритмы не дублируются.
_Avoid_: map соседей (в порядке следования рёбер), sort по требованию (порядок — свойство построения)

**Vertex Degree / deg (степень вершины)**:
В математике в undirected — число рёбер при вершине, петля вносит вклад 2; в directed различают исходящую степень (out-degree, рёбра из вершины) и входящую, петля вносит вклад 1. В проекте Degree — длина списка смежности вершины: петля даёт одну запись списка в обоих режимах, поэтому deg в оценках сложности документации — длина списка соседей, а не классическая undirected степень при наличии петель.
_Avoid_: классическая undirected степень (петля ×2) как значение Degree, входящая степень как directed-значение

**Adjacency Matrix (матрица смежности)**:
Представление графа квадратной матрицей V×V: ячейка отмечает наличие ребра; проверка ребра — O(1), память O(V²). В проекте ячейка логическая (граф невзвешенный); в directed матрица несимметрична, в undirected симметрична. Матрица получается преобразованием из списка смежности и обратно, используется для сравнения представлений и в кадрах, а не как вторая входная модель алгоритмов.
_Avoid_: матрица весов (граф невзвешенный), таблица расстояний (это результат BFS, не представление)

**DFS (обход в глубину, Depth-First Search)**:
Обход, идущий из текущей вершины вдоль одного соседа вглубь до упора, затем возвращающийся (backtracking). В модуле выбран рекурсивный DFS от выбранной стартовой вершины; он возвращает порядок посещения достижимых вершин и не заходит в недостижимые.
_Avoid_: обход дерева (термин обходов Блока 2 — у графа возможны циклы и произвольная связность), итеративный DFS (вариант вне объёма модуля)

**BFS (обход в ширину, Breadth-First Search)**:
Обход от стартовой вершины по слоям: сначала соседи на расстоянии 1, затем 2 и так далее, через FIFO-очередь. Вершина помечается visited при постановке в очередь, поэтому каждая вершина обрабатывается один раз. В невзвешенном графе расстояние BFS до вершины — длина кратчайшего пути.
_Avoid_: поиск в глубину (путаница с DFS), обход по уровням дерева (термин Блока 2; BFS графа работает на произвольном графе)

**Reachability (достижимость)**:
Вершина достижима из стартовой, если существует путь по рёбрам (в directed — по стрелкам) от старта к ней. DFS и BFS возвращают только достижимые вершины; изолированные и чужие компоненты в результат не входят.
_Avoid_: связность (компонентное свойство графа, а не пара «откуда — куда»)

**Connected Component (компонента связности)**:
Математический термин: максимальное множество вершин, попарно достижимых друг из друга (в undirected). Несвязный граф состоит из нескольких компонент; изолированная вершина — компонента из одной вершины. В модуле термин используется концептуально — при обсуждении несвязных графов и того, что поиск циклов сканирует каждую компоненту; отдельного API разметки компонент или визуального режима components модуль не вводит.
_Avoid_: кластер, подграф (произвольная часть графа, не максимальная по достижимости), разметка/нумерация компонент как результат API (модуль её не возвращает)

**Graph Distance (расстояние в графе)**:
Число рёбер на кратчайшем пути между двумя вершинами в невзвешенном графе; у недостижимой вершины пути нет (расстояние не определено) — это нормальный результат «пути нет», не ошибка. BFS от стартовой вершины даёт расстояния до всех достижимых.
_Avoid_: вес (рёбра невзвешенные), длина пути произвольного (не обязательно кратчайшего)

**Cycle (цикл)**:
Путь из вершины в саму себя по рёбрам; петля (self-loop) — цикл в обоих режимах. В directed цикл обнаруживается схемой white/gray/black: свидетель — обратное ребро (back edge) в серую (в рекурсии) вершину. В undirected — парой visited+parent: свидетель — ребро к уже посещённой вершине, которая не является родителем; ребро к родителю циклом не считается. Поиск сканирует все компоненты и останавливается на первом свидетеле.
_Avoid_: повторный визит вершины (в undirected ребро к родителю — не цикл), петля-ребро как «не цикл» (петля считается циклом)

**Back Edge (обратное ребро)**:
Ребро, встреченное DFS на вершину, которая уже находится в текущем пути рекурсии (серая в directed-схеме). В directed-поиске цикла — свидетель цикла; визуализируется подсветкой найденного цикличного ребра.
_Avoid_: обратная дуга произвольного ребра (термин относится к классификации рёбер DFS)

### Процессы

**Orchestrator (Оркестратор)**:
Основная сессия агента, с которой общается пользователь. Управляет потоком из `docs/WORKFLOWS.md`, спавнит субагентов, ведёт статусы. Код от себя не пишет.
_Avoid_: manager, main agent

**Subagent (Субагент)**:
Агент, запущенный оркестратором для специализированной задачи (ревью, реализация). Пользователь с ним не контактирует, результаты возвращаются оркестратору.
_Avoid_: worker, helper

**Checkpoint (Чекпойнт, Ч1–Ч4)**:
Точка потока, где оркестратор останавливается и ждёт явного подтверждения пользователя: спека, тикеты, находки ревью, мерж. Всё остальное автоматизировано.
_Avoid_: gate, approval step

**Flow (Поток)**:
Сценарий процесса под тип работы: A — полный модуль, B — только квиз, C — баг-фикс, D — рефакторинг и процессные/документационные тикеты. Описаны в `docs/WORKFLOWS.md`.
_Avoid_: pipeline, сценарий (кроме заголовка WORKFLOWS.md)

**Backlog (бэклог)**:
Короткий список низкоприоритетных улучшений кода и рефакторинга, замеченных по ходу работы (`docs/BACKLOG.md`); баги и новые фичи в него не попадают. Разбирается на шаге очистки бэклога между модулями (см. `docs/WORKFLOWS.md`).
_Avoid_: техдолг (шире — включает баги), todo-лист

**Friction-лог (лог трения)**:
Короткий лог трения процесса — неудобств agent-workflow, замеченных по ходу работы (`docs/FRICTION_LOG.md`). Отличается от бэклога: фиксирует трение самого процесса, а не улучшения кода. Правила фиксации и триажа — в `docs/WORKFLOWS.md` → «Friction-лог», формат и статусы записей — в `docs/FRICTION_LOG.md`.
_Avoid_: фрикция, фрикшн-лог, список задач

### Визуализатор

**Visualizer (Визуализатор)**:
Веб-приложение (Go-сервер + TS-фронтенд), которое запускает алгоритм с эмиттером и рисует его выполнение.
_Avoid_: visual/, frontend (это имя слоя, не сущность)

**Run**:
Один запуск алгоритма с входными данными: последовательность событий от запуска до конца (или остановки пользователем).
_Avoid_: session, execution, запуск

**Frame / Кадр**:
Снимок визуализации на момент события. Frontend получает поток кадров и рисует их последовательно.
_Avoid_: state, snapshot

**Frame Renderer**:
Адаптер «события алгоритма → кадр для UI» на бэкенде, своя версия под каждый визуализируемый алгоритм (см. ADR-0002).
_Avoid_: mapper, serializer

**Кадр результата операции (result frame)**:
Последний кадр одной команды в Run Trie: строится по отдельному событию результата и — единственный кадр команды — несёт заполненное поле `result` снимка Trie внутри `Frame.Data` (значение из закрытого множества). Стартовый и промежуточные кадры посещения/проверки/pruning той же команды несут `result: null`.
_Avoid_: result-кадр, result-снимок, финальный кадр результата (неунифицированные варианты названия)

**Edge Check (проверка ребра)**:
Поле `edgeCheck` снимка Trie внутри `Frame.Data` — контракт кадра и провода. В каждом кадре посещения/проверки rune — при состояниях `reused`, `created` и `missing` — объект `{ rune: <JSON-строка ровно из одной rune (Unicode scalar value), не числовой код>, state: "reused" | "created" | "missing" }`; в стартовых, промежуточных pruning и кадрах результата операции — ровно `edgeCheck: null`. Состояния ребра: `reused` — существующее ребро; `created` — новое ребро, создаваемое вставкой; `missing` — только попытка поиска/проверки префикса/удаления пройти отсутствующее ребро: отсутствующий потомок не добавляется в топологию и не имеет идентификатора узла, попытка видна через `edgeCheck.rune`. Форма соответствующего библиотечного события определяется публичным API-контрактом тикета 40 и не задаётся этой записью.
_Avoid_: ghost-node/ghost-узел (отсутствующий узел отсутствует в топологии, а не рисуется призраком), status (синоним `state` — дублирование поля не допускается), числовой код rune в `rune` (передаётся строкой)

### Квиз

**Quiz (Квиз)**:
Интерактивный CLI-опросник по темам программы обучения; вопросы сгруппированы по блокам и модулям.
_Avoid_: тест (слишком перегружено), опросник (оставляем как русское имя, не как термин кода)

**Quiz Question (Вопрос квиза)**:
Единица квиза: текст, варианты (или свободный ввод), правильный ответ, пояснение, ссылка на модуль.
_Avoid_: задание, exercise

**Quiz Bank**:
Хранилище вопросов, сгруппированные по блокам/модулям (embedded-файлы или код).
_Avoid_: вопросы.go, question store
