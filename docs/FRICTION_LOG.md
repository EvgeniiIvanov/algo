# FRICTION_LOG.md — лог трения процесса

Короткий список повторяющихся неудобств agent-workflow (OpenCode: orchestrator/implementor/reviewer/tester, permissions, git-workflow, чекпойнты). При обнаружении трения добавьте запись и сразу проведите триаж по правилам `docs/WORKFLOWS.md` → «Friction-лог»; когда запись разобрана (правило или инструкция обновлены либо трение осознанно отклонено), отметьте её статусом.

Правила:

- Одна запись на инцидент или повторяющийся паттерн: **где → что мешало → предлагаемое исправление (если есть)**.
- Сюда идёт только трение процесса (лишние подтверждения, пробелы в workflow, неверно сработавшее permission-правило, неудобная роль агента) — не баги кода и не новые фичи продукта (см. `BACKLOG.md`).
- Записи не привязаны к тикетам модуля: запись — наблюдение о процессе, а не план работы. Но если по записи завели процессный тикет, его номер/ссылка указывается в самой записи.
- Это источник для будущего отдельного репозитория со стандартами (см. `AGENTS.md` → «Переносимость и friction-лог»). Экстракция стандарта — решение пользователя, не раньше второго реального проекта.

Статусы записи (канон — здесь): `open` — трение ещё не устранено: запись ждёт решения либо выполнения связанного процессного тикета (если тикет заведён, запись остаётся `open` и содержит ссылку на него до выполнения тикета); `fixed` — только после фактического устранения трения, со ссылкой на коммит/файл; `rejected` — решено трение не устранять и тикет не заводить, с причиной. Идентификаторы статусов не переводятся.
