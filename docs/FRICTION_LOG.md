# FRICTION_LOG.md — лог трения процесса

Короткий список повторяющихся неудобств agent-workflow (OpenCode: orchestrator/implementor/reviewer/tester, permissions, git-workflow, чекпойнты). При обнаружении трения внесите запись; первичный триаж по влиянию на текущую работу проводится по правилам `docs/WORKFLOWS.md` → «Friction-лог». Статусы записи определяются ниже.

Правила:

- Одна запись на инцидент или повторяющийся паттерн: **где → что мешало → предлагаемое исправление (если есть) → статус**.
- Сюда идёт только трение процесса (лишние подтверждения, пробелы в workflow, неверно сработавшее permission-правило, неудобная роль агента) — не баги кода и не новые фичи продукта (см. `BACKLOG.md`).
- Записи не привязаны к тикетам модуля: запись — наблюдение о процессе, а не план работы.
- Назначение лога и условия выделения стандарта — см. `AGENTS.md` → «Переносимость и friction-лог».

Статусы записи (канон — здесь): `open` — трение ещё не устранено: запись ждёт решения либо выполнения связанного процессного тикета (если тикет заведён, запись остаётся `open` и содержит ссылку на него до выполнения тикета); `fixed` — только после фактического устранения трения, со ссылкой на коммит/файл; `rejected` — дальнейшие действия по записи прекращены с зафиксированной причиной: либо трение решено не устранять (и тикет не заводится), либо после завершившегося тикета решено не заводить follow-up. Идентификаторы статусов не переводятся; записи со статусами `fixed` и `rejected` остаются в логе — это история решений.
