# Кадры (Frame): бэкенд строит снимок состояния, фронтенд — тупой рендерер

Алгоритмы эмитируют события (ADR-0001), но фронтенду нужно рисовать состояние. Решили: после каждого события **Frame Renderer** на бэкенде строит полный снимок — структура данных (массив/дерево/граф), подсветки, текст пояснения. Фронтенд получает массив кадров и просто их отрисовывает.

Вариант «события-действия, фронтенд сам накапливает состояние» отвергнут: для каждого типа структуры нужна логика воспроизведения на клиенте, а перемотка назад требует переигрывания событий. Кадры дают паузу/перемотку/скорость почти бесплатно и изолируют фронтенд от деталей алгоритмов.

## Considered Options

- **Кадры со снапшотами** (выбрано): тупой фронтенд, бесплатная перемотка, цена — обвязка Frame Renderer на бэкенде.
- **События-действия + накопление состояния на клиенте**: отвергнуто — умный клиент, сложная перемотка.
