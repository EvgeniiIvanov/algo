# SSE для стрима кадров вместо WebSocket

Кадры выполнения — односторонний поток, пауза/перемотка/скорость управляются клиентом локально над уже полученными кадрами, новый ввод данных = новый запрос. Поэтому **SSE**: радикально проще WebSocket, half-duplex здесь не ограничение. Если позже понадобится живое управление запуском (команды с клиента в процессе выполнения), вернёмся к вопросу.
