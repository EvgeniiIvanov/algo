# 11: Односвязный список сквозным срезом

**What to build:** односвязный список появляется в визуализаторе: выбор «связный список», сценарий (`prepend 4`, `append 7`, `insert 1 9`, `remove 0`, `find 7`), кадры **узлами со стрелками next** — видно, что память не непрерывна и обход идёт узел за узлом (подсветка текущего узла при find/insert/remove). В библиотеку добавляется LinkedList на указателях с событиями обхода и переключения связей. Спека: `docs/SPEC.md`, секция модуля «Списки, стек и очередь».

**Blocked by:** 10 (список на слайсе сквозным срезом).

**Status:** done

## Notes

- Адреса памяти узлов не показываем (out of scope модуля) — стрелки схематичны.
- Двусвязный/циклический списки, Reverse/Sort — out of scope.
- **Семантика Find изменена относительно черновика осознанно**: черновик реализовал `Find(i int) (int, error)` — поиск по индексу (копия Get). Тикет, спека и сценарий UI используют `find 7` — поиск по значению: `Find(value int) int` возвращает позицию первого узла с искомым значением, при промахе -1; промах — не ошибка (как у бинарного поиска трейсера). Заодно это открывает учебную точку модуля: видимая цена обхода узел за узлом.
- Черновик сверх минимума задал PopFront/PopBack/IsEmpty с поддержкой tail/size — оставлены как есть (снятие с хвоста полезно для инварианта tail и наглядно против списка на слайсе: rear-удаление за O(n)).
- Ошибки пакета структур централизованы: `ErrListEmpty`, `ErrIndexOutOfRange`, `ErrQueue*`, `ErrStack*` — в новом `algorithms/structures/errors.go` (вариант пользователя; из list.go/queue.go/stack.go дубли удалены).
- События (ADR-0001): LinkedVisit (обход), LinkedLink (переключение next с позицией узла), LinkedInsert/LinkedRemove (с позициями и значениями), LinkedFound/LinkedNotFound (результат find). Каждое событие — один кадр (ADR-0002), поэтому prepend даёт один кадр, а вставка по позиции — визиты + связь + вставка: обход виден глазами; визиты есть и при remove по позиции, и при append (один кадр связи).
- Пределы Run односвязного списка — те же safety bound визуализации, что у списка на слайсе (500 операций, 100 узлов), зеркалятся на фронте; библиотечный LinkedList их не имеет. В кадрах capacity = числу узлов: скрытой «ёмкости» у узлов нет.
