# 17: Согласование агентного процесса (OpenCode-only)

**What to build:** процессная документация, профили агентов и скиллы должны описывать один согласованный сценарий работы: автоматизация только в OpenCode (оркестратор строго не кодит, реализация — субагентом `implementor` в worktree тикета); учебный черновик пользователя — явный блокирующий чекпойнт Ч2.5; ревью — две независимые оси двумя свежими дочерними сеансами `reviewer`; git-политика (локальные коммиты после проверок, push только с одобрением, мерж и интеграция — человек, чистка worktree после мержа). Без правок исходников приложения.

**Blocked by:** — (процессный тикет, без зависимостей).

**Status:** in-progress

**автор-черновик:** не применим (тикет не библиотечный — код/структура не затрагиваются).

## Acceptance Criteria

- [ ] `AGENTS.md`, `docs/WORKFLOWS.md` и профили `.opencode/agents/*.md` согласованы: OpenCode — единственный хост агентов, VS Code — только место для черновиков пользователя; контекст задачи — всегда `AGENTS.md` + `docs/WORKFLOWS.md`, тикет/spec и только релевантные ADR/глоссарий.
- [ ] Оркестратор строго не реализует код: вся реализация делегируется субагенту `implementor` в worktree тикета; спавнить можно только `implementor`, `reviewer`, `tester` (нативный `permission.task`).
- [ ] Ч2.5 (черновик алгоритма/структуры пишет пользователь) — явный блокирующий чекпойнт: реализация библиотечного тикета не стартует без черновика.
- [ ] Тесты пишет `implementor`; `tester` — необязательная read-only риск-оценка, не автор тестов.
- [ ] Ревью: две независимые оси Standards + Spec двумя параллельными свежими дочерними сеансами субагента `reviewer` (read-only); источники Spec-оси локальные (`docs/tickets/`, `docs/SPEC.md`), без требования `docs/agents/issue-tracker.md`.
- [ ] Жизненный цикл worktree → реализация → ревью → мерж → чистка явно описан как повторяющийся на каждый тикет, а не раз на модуль; чистка после подтверждённого мержа выполняется оркестратором из основной папки с одобрением пользователя, без force и без удаления удалённых веток.
- [ ] Git-policy: имплементор проверяет свою ветку `ticket/...` инструкцией (не негативным permission), коммитит локально после проверок; push — с одобрением (permission `ask`), `push --force` запрещён; мерж в `main`, force push и удаление веток имплементору недоступны.
- [ ] Нативные permissions: у `reviewer` и `tester` запрещён edit и узкий read-only allowlist shell-команд (инспекционные git-команды; для `tester` — точная команда `make test`).
- [ ] Из всех четырёх профилей `.opencode/agents/*.md` удалено `temperature` из frontmatter (не поддерживается в OpenCode V2).
- [ ] Скилл `code-review` согласован с репозиторием: фиксированная точка по умолчанию `main...HEAD` (если пользователь не задал иную), локальные источники тикета/spec, два параллельных свежих `reviewer`-ребёнка с отдельными промптами осей, без блокировки на issue-tracker.
- [ ] Скилл `implement` согласован с git-политикой (локальный коммит после проверок на своей ветке тикета; push только с одобрением; мерж в `main` — никогда); скилл `implement-spec` не тронут и явно помечен вне канонического потока репозитория.
