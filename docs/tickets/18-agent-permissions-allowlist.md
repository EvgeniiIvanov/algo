# 18: Уточнение allowlist permissions (read-only-инспекции и точные команды)

**What to build:** расширить общий read-only инспекционный allowlist в `opencode.json` только тремя перечисленными правилами с обязательным аргументом (`git branch --list ?*`, `git ls-remote --heads origin ?*`, `git -C ../algo-* status ?*`), добавить в allowlist имплементора одну точную команду `gofmt -l quiz`; не добавлять широких паттернов (`git *`, `go *` и т. п.), allow-обёрток пайплайнов и мутационных прав; `git pull` остаётся под одобрением (fallback `shell *` → `ask`); permissions `reviewer` и `tester` не расширяются. Процессная документация и комментарии в профилях должны точно описывать фактические правила и границы ролей, включая то, что text-based shell-матчинг glob'ами — не песочница для произвольных обёрток, а общие правила не отменяют профильные deny `reviewer`/`tester`. Deny-правила не меняются.

## Acceptance Criteria

- [x] В общий read-only инспекционный allowlist `opencode.json` добавлены ровно три правила **с обязательным аргументом**: `git branch --list ?*`, `git ls-remote --heads origin ?*`, `git -C ../algo-* status ?*`; они размещены в read-only-секции (до общего `git push *` → `ask`) и конфликта с нативными deny не создают (`--list` — листинг, не мутация). Семантика `?*` отражена в паттернах и документации: в OpenCode V2 хвостовой литеральный ` *` матчится особым образом и покрывает также команды без аргументов, поэтому `?*` требует хотя бы один аргумент; формы без аргументов остаются под одобрением (`ask`), а примеры с аргументами остаются разрешёнными.
- [x] В allowlist `implementor` добавлена ровно одна точная команда `gofmt -l quiz`; существующие точные build/test/lint-права (цели make, go build/vet/test ./..., golangci-lint run ./..., pnpm-скрипты, `git add`/`git commit`) сохранены без изменений.
- [x] `git pull` остаётся без allow-правила и требует одобрения через fallback `shell *` → `ask`; широкие паттерны (`git *`, `go *` и т. п.), allow для пайплайнов/обёрток и мутационные права не добавлены.
- [x] Permissions `reviewer` и `tester` не расширены (файлы не тронуты); документация явно фиксирует, что общие allow-правила `opencode.json` **не отменяют** их профильный blanket shell-deny — их узкие re-allow живут в их профилях.
- [x] Документация (`AGENTS.md`, комментарий в профиле `implementor`, этот тикет) точно описывает фактические правила без дублированных перечислений: `opencode.json` — авторитетный полный список общих инспекций, профиль имплементора — авторитетный список его собственных allow; описана точная команда `gofmt -l quiz` (в том числе в Git-policy имплементора), `git pull` под одобрением и то, что glob-матчинг по разобранным сегментам команды — не песочница для произвольных обёрток (произвольные команды требуют одобрения OpenCode).
- [x] Существующие deny-правила не изменены; командные примеры из пункта 1 проверены против итогового allowlist (текстовая проверка по алгоритму сопоставления OpenCode).
- [x] Deny-правила `git branch --list` для `-d`/`-m` **осознанно не добавляются** — принято решение пользователя (Ч3): текущее поведение Git и предоставленное ревью-доказательство (git сам отвергает комбинацию `--list` с `-D`, exit 129, ветка не удаляется) считаются достаточными.
