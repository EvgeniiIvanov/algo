# 18: Уточнение allowlist permissions (read-only-инспекции и точные команды)

**What to build:** расширить общий read-only инспекционный allowlist в `opencode.json` только тремя перечисленными правилами (`git branch --list *`, `git ls-remote --heads origin *`, `git -C ../algo-* status *`), добавить в allowlist имплементора одну точную команду `gofmt -l quiz`; не добавлять широких паттернов (`git *`, `go *` и т. п.), allow-обёрток пайплайнов и мутационных прав; `git pull` остаётся под одобрением (fallback `shell *` → `ask`); permissions `reviewer` и `tester` не расширяются. Процессная документация и комментарии в профилях должны точно описывать фактические правила и границы ролей, включая то, что text-based shell-матчинг glob'ами — не песочница для произвольных обёрток. Deny-правила не меняются.

**Blocked by:** 17 (схема permissions V2 и централизованный инспекционный allowlist уже введены там).

**Status:** in-progress

**автор-черновик:** не применим (тикет процессный — исходники приложения не затрагиваются).

## Acceptance Criteria

- [x] В общий read-only инспекционный allowlist `opencode.json` добавлены ровно три правила: `git branch --list *`, `git ls-remote --heads origin *`, `git -C ../algo-* status *`; они размещены в read-only-секции (до общего `git push *` → `ask`) и конфликта с нативными deny не создают (`--list` — листинг, не мутация). Формы без аргументов (`git branch --list` и т. п.) из-за хвостового `*` не совпадают и остаются под одобрением (`ask`) — это безопасный fallback, а не расширение.
- [x] В allowlist `implementor` добавлена ровно одна точная команда `gofmt -l quiz`; существующие точные build/test/lint-права (цели make, go build/vet/test ./..., golangci-lint run ./..., pnpm-скрипты, `git add`/`git commit`) сохранены без изменений.
- [x] `git pull` остаётся без allow-правила и требует одобрения через fallback `shell *` → `ask`; широкие паттерны (`git *`, `go *` и т. п.), allow для пайплайнов/обёрток и мутационные права не добавлены.
- [x] Permissions `reviewer` и `tester` не расширены (файлы не тронуты).
- [x] Документация (`AGENTS.md`, комментарий в профиле `implementor`, этот тикет) точно описывает фактические правила: три новых read-only инспекционных правила, точную команду `gofmt -l quiz`, `git pull` под одобрением и то, что glob-матчинг по разобранным сегментам команды — не песочница для произвольных обёрток (произвольные команды требуют одобрения OpenCode).
- [x] Существующие deny-правила не изменены; командные примеры из пункта 1 проверены против итогового allowlist (текстовая проверка совпадений по правилам `opencode.json`).
