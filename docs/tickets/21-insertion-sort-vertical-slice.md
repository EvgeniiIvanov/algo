# 21: Insertion sort — сквозной вертикальный срез

**What to build:** учащийся может выбрать insertion sort и увидеть, как алгоритм берёт очередной элемент, сдвигает большие значения вправо и вставляет элемент в отсортированную часть.

**Blocked by:** 19 (Bubble sort — сквозной вертикальный срез).

**Status:** done

Спека: `docs/SPEC.md`, модуль «Простые сортировки».

`автор-черновик: человек` — пользователь пишет черновик insertion sort в библиотеке алгоритмов и явно подтверждает его на Ч2.5; до этого реализация не начинается.

## Acceptance Criteria

- [x] Библиотечный insertion sort сортирует `[]int` по возрастанию на месте, включая пустой/одноэлементный входы, отрицательные числа и дубликаты; элементы, равные ключу, не сдвигаются друг за друга, поэтому выбранный вариант устойчив.
- [x] Quiet mode не эмитирует события и не аллоцирует; типизированные события сравнения (с явным исходом больше/равно/меньше), сдвига и вставки позволяют показать каждый шаг без скрытой смены состояния, «дырка» и удерживаемый ключ несут в событиях явно, а каждый проход завершается видимым событием вставки — в том числе без сдвигов («ключ уже на месте»). Публичные тесты проверяют результат и известную последовательность событий.
- [x] Insertion sort доступен в существующем интерфейсе запуска сортировок и использует общий контракт ввода и ограничение 100 элементов; сравнения, сдвиги и вставка показаны самодостаточными `kind="sort"` кадрами с подсветкой индексов, пустой позицией-«дыркой» и удерживаемым ключом в снимке, с русскими пояснениями; старые снимки `kind="sort"` без `gap`/`key` остаются валидными и рисуются без UI вставки.
- [x] Интеграционные тесты проверяют SSE-кадры и конечное состояние insertion sort; публичные frontend-тесты подтверждают выбор алгоритма и рендер его кадров. Bubble sort и selection sort, а также прежние визуализации продолжают работать.
- [x] Go build/vet/test и lint, а также frontend lint/test/build проходят.
