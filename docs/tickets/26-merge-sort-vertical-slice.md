# 26: Merge sort — сквозной вертикальный срез

**What to build:** учащийся может выбрать merge sort, задать массив целых чисел и увидеть, как рекурсивное деление и стабильное слияние упорядочивают его по возрастанию.

**Blocked by:** None (can start after user-authored draft and CH2.5)

**Status:** ready-for-agent

`автор-черновик: человек` — до реализации пользователь пишет и подтверждает черновик merge sort на Ч2.5.

## Acceptance Criteria

- [ ] Библиотечный merge sort сортирует переданный `[]int` по возрастанию; пустой и одноэлементный входы, отрицательные числа и дубликаты поддерживаются. Выбран top-down вариант со стабильным слиянием (при равенстве первым берётся элемент левой части); вспомогательная память — O(n), время — O(n log n) во всех случаях.
- [ ] Quiet mode возвращает отсортированный результат; с Emitter типизированные события сравнений и записей позволяют восстановить существенные шаги слияния. Публичные тесты проверяют результат и известную последовательность событий, включая выбор левой части при равных значениях как свидетельство стабильного слияния.
- [ ] Merge sort доступен в визуальном Run с общим контрактом массива и лимитом 100 элементов; невалидный ввод и превышение лимита отклоняются до SSE. Кадры `kind="sort"` — полные снимки, показывающие активные части, сравнения и записи при слиянии, с русскими пояснениями; общий transport/player не меняется.
- [ ] Frontend позволяет выбрать merge sort, зеркально валидирует ввод и строит правильный URL; публичные тесты проверяют URL и рендер новых ролей/диапазонов. Bubble, selection и insertion sort продолжают работать без изменения контрактов.
- [ ] SSE-тест проходит от запроса до известной последовательности кадров и финального отсортированного массива; покрыты пустой и одноэлементный входы, отрицательные числа, дубликаты, а также отказ от невалидного входа/лимита до SSE.
- [ ] Go build/vet/test и lint, а также frontend lint/test/build (frozen install) проходят.
