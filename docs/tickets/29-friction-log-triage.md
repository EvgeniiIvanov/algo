# 29: Триаж friction-лога и приоритет процессных задач

**What to build:** процессный тикет: трение процесса сейчас фиксируется в `docs/FRICTION_LOG.md`, но разбирается только на шаге очистки бэклога между модулями — неудобство, замеченное по ходу работы, может ждать неделями и даже блокировать текущую работу. Договариваемся о времени реакции и приоритете: новую friction-запись триажим сразу при замечании; блокирующее или повторяющееся трение оформляется приоритетной процессной задачей и решается раньше обычных задач бэклога; активную работу прерываем только при реальной блокировке, в остальных случаях решение принимается на безопасной границе. Заодно уточняется фактическое описание allowlist в существующей записи лога (разрешены проверочные цели `Makefile` и только frontend-скрипты `lint`/`test`/`build`, не «все Makefile-цели/package scripts») и согласуются статусы записей (`open` / `fixed` / `rejected`). Без правок исходников приложения.

**Blocked by:** — (процессный тикет, без зависимостей).

**Status:** in-progress

**автор-черновик:** не применим (тикет процессный — исходники приложения не затрагиваются).

## Acceptance Criteria

- [ ] `docs/FRICTION_LOG.md`: существующая запись о allowlist описывает фактическое состояние — разрешены проверочные цели `Makefile` и только frontend-скрипты `lint`/`test`/`build` (плюс `pnpm install --frozen-lockfile`); не утверждается, что разрешены все Makefile-цели или package scripts; указано, что runtime-цели (`make run-*`) и `pnpm dev` / `preview` / `test:watch` в allowlist не входят. Историческая запись и её смысл сохранены.
- [ ] `docs/FRICTION_LOG.md`: нет противоречия между «запись не привязана к тикетам» и требованием указывать процессный тикет: запись — наблюдение о процессе, а не план работы; если по записи завели процессный тикет, его номер/ссылка указывается в самой записи.
- [ ] Статусы friction-записей согласованы и не переводятся: `open` / `fixed` / `rejected`; описания — на русском, идентификаторы статусов — английские. Смысл статусов: `open` — трение ещё не устранено (ожидает решения либо выполнения связанного тикета, при заведённом тикете запись остаётся `open` со ссылкой до его выполнения; не сводится только к ожиданию решения); `fixed` — только после фактического устранения трения, со ссылкой на коммит/файл; `rejected` — решено не устранять и тикет не заводить, с причиной.
- [ ] `docs/WORKFLOWS.md`: опечатка `отрыто` исправлена; описан немедленный триаж новой friction-записи по ходу любой работы; критерии приоритета: блокирующее или повторяющееся трение оформляется приоритетной процессной задачей (тикет потока D) и решается раньше обычных задач бэклога; активная работа прерывается только при реальной блокировке, в остальных случаях — на безопасной границе; числовая система приоритетов не вводится; новые чекпойнты не вводятся.
- [ ] `docs/WORKFLOWS.md`: на шаге очистки бэклога записи friction-лога разбираются до обычных записей `BACKLOG.md` (приоритет процессных задач соблюдается); запись с незавершённым связанным тикетом остаётся `open` со ссылкой — требуется лишь проверка, что тикет остаётся приоритетным; непривязанные мелкие записи решаются явно: либо тикет, либо `rejected` с причиной.
- [ ] `docs/FRICTION_LOG.md` сам сообщает про связь `open`-записей с процессными тикетами; `docs/WORKFLOWS.md` и `docs/FRICTION_LOG.md` не противоречат друг другу.
- [ ] Каноническая логика триажа, приоритета и очистки — только в `docs/WORKFLOWS.md`; `AGENTS.md`, `GLOSSARY.md` и `docs/FRICTION_LOG.md` содержат лишь краткое описание/формат/указатель и не пересказывают полный порядок. В `GLOSSARY.md` статусные идентификаторы трения не перечисляются, если канон статусов в `docs/FRICTION_LOG.md`. Различие Friction-лог ↔ Backlog сохранено.
- [ ] Слово «сырьё» в значении «материал для будущего стандарта» заменено на «источник» (или переформулировано) в `AGENTS.md` и `docs/FRICTION_LOG.md`.
- [ ] `AGENTS.md`: агент при замечании трения фиксирует и триажит его по ходу работы — короткий указатель на правила в `docs/WORKFLOWS.md`, без дублирования подробного workflow.
- [ ] `GLOSSARY.md`: согласованность терминов проверена; краткое определение friction-лога добавлено рядом с Backlog без дублирования определений.
- [ ] Вводная фраза `docs/FRICTION_LOG.md` грамматически корректна (императив: «При обнаружении трения добавьте запись и сразу проведите триаж…»); русская грамматика и терминология выверены во всех затронутых файлах.
- [ ] Документация непротиворечива между собой и с фактическим allowlist в профиле `implementor` (`AGENTS.md`, `docs/WORKFLOWS.md`, `docs/FRICTION_LOG.md`, `docs/BACKLOG.md`, `GLOSSARY.md`, статусы существующих тикетов); правки — только документация/процесс: исходники приложения, `docs/SPEC.md` и `PROGRESS.md` не затрагиваются.
