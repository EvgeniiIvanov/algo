# 31: Бинарное дерево и обходы в глубину — сквозной вертикальный срез

**What to build:** учащийся задаёт произвольное бинарное дерево, выбирает in-order, pre-order или post-order и видит последовательность посещения узлов на визуализации дерева.

**Blocked by:** None (реализация начинается после утверждения тикетов на Ч2 и пользовательского черновика на Ч2.5).

**Status:** draft (Ч2 pending)

Спека: `docs/SPEC.md`, модуль «Обходы бинарного дерева».

`автор-черновик: человек` — пользователь пишет черновик модели бинарного узла и трёх обходов в глубину в `algorithms/trees` и явно подтверждает его на Ч2.5; до этого реализация не начинается.

## Acceptance Criteria

- [ ] В `algorithms/trees` есть общая модель бинарного дерева: узел с целочисленным значением и левым/правым потомками; модель не навязывает свойства BST, допускает повторяющиеся значения и используется обходами.
- [ ] In-order, pre-order и post-order возвращают значения в определённом спекой порядке; пустой корень даёт пустой результат. Публичные тесты покрывают пустое, одноузловое, асимметричное, перекошенное дерево и повторяющиеся значения.
- [ ] В quiet mode обходы работают без событий; с Emitter типизированные события позволяют определить посещаемый узел и восстановить порядок посещений, не смешивая узлы с одинаковыми значениями. Тесты проверяют известный порядок событий.
- [ ] `docs/algorithms/` содержит учебное описание модели и реализованных трёх обходов с записью в индекс `docs/algorithms/README.md`. Документация добавляется после подтверждения черновика на Ч2.5 и отражает реализацию.
- [ ] Визуальный Run принимает вложенный JSON дерева (`value`, `left`, `right`) и один из трёх порядков; отсутствующие/`null` потомки и верхний `null` обрабатываются по спеке. Невалидный JSON и дерево более 100 узлов отклоняются до SSE; библиотечные функции этим лимитом не ограничены.
- [ ] `GET /api/run/tree-traversal` принимает URL-кодированные параметры `tree` (JSON) и `order` (`in-order`, `pre-order` или `post-order`); неизвестный порядок и некорректные параметры отвергаются до SSE.
- [ ] `kind="tree"` содержит полный снимок топологии, стабильные идентификаторы узлов, активный узел, уже посещённые узлы с порядком и русское пояснение. Идентификатор не зависит от значения узла. Есть исходный кадр и кадр на каждое событие.
- [ ] Фронтенд позволяет ввести дерево и выбрать любой из трёх порядков, зеркально проверяет JSON и лимит, строит URL запуска и рендерит кадры нового вида дерева. Публичные тесты покрывают корректный/некорректный ввод и рендер несимметричного дерева с повторяющимися значениями; существующие визуализации не ломаются.
- [ ] SSE-интеграционные тесты проверяют все три порядка на известном дереве, пустое дерево и отказ от невалидного ввода/лимита до начала SSE.
- [ ] Go build/vet/test и lint, а также frontend lint/test/build (frozen install) проходят.
