# 32: Обход бинарного дерева по уровням — сквозной вертикальный срез

**What to build:** учащийся выбирает обход по уровням на том же бинарном дереве и видит посещение слева направо по уровням вместе с состоянием FIFO-очереди.

**Blocked by:** 31 (требуются модель дерева, ввод и визуализация из первого вертикального среза; реализация начинается после пользовательского черновика и Ч2.5).

**Status:** draft (Ч2 pending)

Спека: `docs/SPEC.md`, модуль «Обходы бинарного дерева».

`автор-черновик: человек` — пользователь пишет черновик обхода по уровням в `algorithms/trees` и явно подтверждает его на Ч2.5; до этого реализация не начинается.

## Acceptance Criteria

- [ ] Обход по уровням использует FIFO-порядок и посещает узлы слева направо на каждом уровне; пустой корень даёт пустой результат. Публичные тесты проверяют пустое, одноузловое, асимметричное и перекошенное дерево, а также повторяющиеся значения.
- [ ] Quiet mode возвращает значения в порядке посещения; типизированные события с Emitter дают достаточно данных, чтобы визуализировать очередь и посещённый узел. Тесты проверяют известный результат и значимую последовательность событий.
- [ ] Учебная документация из тикета 31 дополнена обходом по уровням и отражает его реализованный вариант; запись в `docs/algorithms/README.md` остаётся актуальной.
- [ ] `GET /api/run/tree-traversal` принимает `order=level-order` с тем же параметром `tree`; существующий маршрут сохраняет совместимость трёх DFS-режимов. Визуальный лимит — не более 100 узлов; невалидный ввод и превышение лимита отвергаются до SSE.
- [ ] Кадры `kind="tree"` показывают полный снимок дерева, активный узел, посещённые узлы с порядком и FIFO-очередь с идентификаторами узлов; текст пояснения на русском объясняет добавление/удаление узлов из очереди. Общий SSE-транспорт и плеер не меняются.
- [ ] Фронтенд добавляет выбор обхода по уровням и отображение очереди, сохраняя работу in-order, pre-order и post-order. Публичные тесты проверяют разбор выбора режима и рендер кадра с повторяющимися значениями и непустой очередью.
- [ ] SSE-интеграционный тест проверяет известное дерево, последовательность кадров и финальный порядок обхода по уровням; пустое дерево и отказ до SSE также покрыты.
- [ ] Go build/vet/test и lint, а также frontend lint/test/build (frozen install) проходят.
