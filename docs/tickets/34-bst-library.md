# 34: BST — операции библиотеки

**What to build:** учащийся может вставлять, искать и удалять уникальные целочисленные ключи в бинарном дереве поиска и проверять операции без визуализатора.

**Blocked by:** 33 (модуль обходов завершён; используется общая модель `trees.Node`).

**Status:** planned

Спека: `docs/SPEC.md`, модуль «BST: вставка, поиск и удаление».

`автор-черновик: человек` — пользователь пишет черновик операций BST в `algorithms/trees` и явно подтверждает его на Ч2.5; до этого реализация не начинается.

## Acceptance Criteria

- [ ] Публичные операции вставки, поиска и удаления работают поверх общей модели `trees.Node`; контракт позволяет вернуть новый корень, если операция меняет корень дерева.
- [ ] BST поддерживает строгий порядок: значения слева меньше узла, справа — больше. Повторная вставка существующего ключа не меняет дерево и сообщает, что вставка не выполнена.
- [ ] Поиск найденного и отсутствующего ключа, пустое дерево и удаление отсутствующего ключа имеют определённые результаты; промахи не являются ошибками.
- [ ] Удаление корректно обрабатывает лист, узел с одним ребёнком, узел с двумя детьми через inorder-successor и удаление корня. После каждой операции BST-инвариант сохраняется.
- [ ] Quiet mode и типизированные события дают одинаковое поведение; события позволяют восстановить существенные сравнения, переходы по ветвям, результат операции и структурные изменения, включая работу с successor.
- [ ] Публичные API-тесты проверяют операции на пустом, одноузловом, асимметричном и перекошенном дереве; последовательности операций, дубликат, промахи, удаление корня и все три случая удаления. Событийные тесты фиксируют значимую последовательность шагов, не внутреннюю реализацию.
- [ ] Учебная документация BST добавлена в `docs/algorithms/` и индекс `docs/algorithms/README.md`; `GLOSSARY.md` дополнен принятыми терминами BST и inorder-successor.
- [ ] `go build ./...`, `go vet ./...`, `go test ./...` и `golangci-lint run ./...` проходят.
