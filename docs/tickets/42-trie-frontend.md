# 42: Trie — фронтенд сценария и кадров

**What to build:** учащийся задаёт сценарий Trie во фронтенде, запускает его и видит обход по rune, отметки конца слова и изменённое дерево на каждом кадре.

**Blocked by:** 41 (нужен контракт серверного Run и снимков `kind="trie"`).

**Status:** planned

Спека: `docs/SPEC.md`, модуль «Trie: вставка, поиск, префиксы и удаление».

## Acceptance Criteria

- [ ] Во фронтенде доступен сценарий Trie с командами `insert W`, `search W`, `prefix W`, `delete W`; стартовое дерево пустое.
- [ ] Публичная проверка входа зеркалирует серверные правила: один непустой Unicode-токен без пробелов, до 100 rune в слове/префиксе, до 500 команд; пустые строки и строки только из пробелов игнорируются, сценарий без единой команды отвергается; Run URL корректно кодирует `script` для `GET /api/run/trie` и совпадает с серверным контрактом.
- [ ] Публичная симуляция сценария (dry-run) в TS считает итоговое число живых rune-узлов до Run (корень не считается) и зеркально проверяет лимит в 100 живых rune-узлов так же, как сервер до SSE; превышение лимита и иные нарушения отвергаются до отправки Run.
- [ ] Кадры `kind="trie"` принимаются и рендерятся: произвольное ветвление, отметки конца слова, активный путь, явный результат операции (вставлено/уже было, найдено/не найдено, префикс найден/не найден, удалено/не удалено) и итог шага видны в каждом снимке.
- [ ] Рендер работает с идентификаторами узлов — путями по rune-меткам рёбер в однозначном кодировании кадра — без предположения о межкадровой стабильности и без L/R-контракта бинарного `NodeID`.
- [ ] Публичные тесты проверяют допустимый/недопустимый сценарий (включая игнорирование пустых строк/строк из пробелов и отказ сценария без команд), dry-run лимита живых узлов, построение URL и рендер кадров вставки с общим префиксом, точного поиска и промаха, проверки префикса и удаления с pruning.
- [ ] UI и фронтенд-тесты прежних визуализаций (обходы, BST) продолжают работать без изменения их поведения; контракт `kind="tree"` не меняется.
- [ ] `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm test` и `pnpm build` проходят.
