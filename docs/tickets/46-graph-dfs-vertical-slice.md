# 46: Графы — рекурсивный DFS: сквозной вертикальный срез (библиотека, кадры, SSE, фронтенд)

**What to build:** учащийся задаёт граф числом вершин и списком рёбер, выбирает стартовую вершину и видит пошаговый рекурсивный DFS: порядок посещения достижимых вершин, вход в вершину, движение по рёбрам, возвраты рекурсии — на кадрах `kind="graph"` с полной топологией и обоими представлениями.

**Blocked by:** 45 (нужны модель графа, список смежности и преобразования).

**Status:** draft — ожидает утверждения на Ч2

Спека: `docs/SPEC.md`, модуль «Основы графов: представления, DFS, BFS и циклы».

`автор-черновик: человек` — пользователь пишет черновик рекурсивного DFS и его типизированных событий в `algorithms/graphs` и явно подтверждает его на Ч2.5; до этого реализация тикета не начинается. Учебная документация `docs/algorithms/` (DFS) добавляется после подтверждения черновика и до завершения тикета.

## Acceptance Criteria

- [ ] В `algorithms/graphs` есть рекурсивный DFS поверх списка смежности: старт от выбранной вершины, возврат порядка посещения достижимых вершин (недостижимые не входят); соседи перебираются в порядке возрастания номеров. Для матрицы DFS не реализуется.
- [ ] Quiet mode даёт тот же результат без событий; с Emitter типизированные события показывают вход в вершину, движение по ребру, выход из вершины (finish), текущий путь рекурсии и состояние visited — достаточно, чтобы Frame Renderer строил кадры, не зная внутренностей (ADR-0001).
- [ ] Установлен маршрут `GET /api/run/graph` с query-параметрами: `vertices` — целое число вершин (визуальный диапазон 0..20), `edges` — URL-кодированные строки `u v` через перевод строки (параметр обязателен и при пустом значении: пустая строка — граф без рёбер, только изолированные вершины; опущенный `edges` — ошибка; не более 100 строк), `directed` — ровно `true` или `false`, `mode` — ровно `dfs`, `bfs` или `cycles`; `start` обязателен только для `dfs`/`bfs`, `target` опционален и только для `bfs`. В этом тикете реализуется режим `dfs`. Имена и семантика полей закреплены спекой. Плохие, отсутствующие или вне-диапазона параметры — неизвестный `mode`, нецелое или вне 0..20 `vertices`, `directed` не `true`/`false`, опущенный или нецелый `edges`, отсутствие обязательного `start`, `start`/`target` вне `0..vertices-1`, заданные `start` или `target` в `cycles`, `target` в `dfs`, нецелые или вне диапазона `u v`, дубликаты рёбер (в undirected `(u,v)` и `(v,u)` — один дубликат; в directed противоположные направления — разные рёбра), неверный старт — отвергаются до Run.
- [ ] `dfs` и `bfs` при `vertices` = 0 отвергаются до SSE: обязательный `start` не существует; `cycles` на пустом графе (0 вершин) — валидный Run с результатом «циклов нет».
- [ ] Лимиты визуального Run проверяются до SSE: вершины в диапазоне 0..20 и не более 100 рёбер; это safety bounds визуализации, библиотека лимитов не имеет. Сервер и фронтенд зеркально валидируют ввод и лимиты до начала SSE.
- [ ] Гранулярность событий закреплена (ADR-0001) и даёт консервативную верхнюю границу потока: DFS эмитирует вход в вершину, не более одного события на каждую проверку элемента списка смежности и выход из вершины; BFS — не более одного события постановки в очередь (несёт отметку visited и расстояние) и одного события извлечения на каждую достижимую вершину плюс не более одного события на каждую проверку элемента списка смежности; режим циклов — вход/переход цвета и выход/переход цвета на каждую достигнутую вершину, не более одного события на каждую проверку элемента списка смежности и не более одного итогового события результата. Начальный кадр добавляет один. В directed суммарно E элементов списков смежности, в undirected — не более 2E, поэтому верхняя граница потока для всех трёх режимов — 2V + 2E + 2 кадров, при V ≤ 20 и E ≤ 100 — не более 242 кадров.
- [ ] Новый `kind="graph"` — полный самодостаточный снимок (ADR-0002): вся топология (вершины `0..n-1`, рёбра, флаг directed/undirected), оба представления (список и матрица) видны в кадре, позиции вершин детерминированы (круговая раскладка), изолированные вершины и несвязные графы рендерятся; есть активная вершина/путь рекурсии, посещённые вершины с порядком, состояние режима и пояснение на русском. Запуск начинается с исходного кадра, далее кадр на событие; верхняя граница потока — 2V + 2E + 2 кадров (≤ 242 при лимитах), см. гранулярность событий выше.
- [ ] Фронтенд позволяет ввести граф и старт, зеркально проверяет ввод и лимиты, строит URL запуска и рендерит `kind="graph"`; существующие визуализации, `kind="tree"`, общий SSE-транспорт и плеер не меняются.
- [ ] Тесты на швах: публичный API (quiet + emitter-шпион на известном графе: порядок посещения, вход/ребро/выход, путь рекурсии, visited; несвязный граф, изолированная стартовая вершина, старт из вершины без рёбер); SSE-интеграция (запрос `GET /api/run/graph` с известным графом → последовательность кадров `kind="graph"`, включая граф без рёбер, и число кадров в пределах верхней границы, ошибки ввода и лимитов до SSE); фронтенд (разбор ввода, URL маршрута `/api/run/graph`, зеркальная валидация, рендер графа с изолированной вершиной и графа без рёбер; DOM ниже публичного renderer-интерфейса и `fetch` без инъекции не тестируются).
- [ ] `go build ./...`, `go vet ./...`, `go test ./...` и `golangci-lint run ./...` проходят; для фронтенда `pnpm install --frozen-lockfile` + lint/test/build проходят.
- [ ] Имплементор не меняет `PROGRESS.md`.
