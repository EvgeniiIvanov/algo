# 46: Графы — рекурсивный DFS: сквозной вертикальный срез (библиотека, кадры, SSE, фронтенд)

**What to build:** учащийся задаёт граф числом вершин и списком рёбер, выбирает стартовую вершину и видит пошаговый рекурсивный DFS: порядок посещения достижимых вершин, вход в вершину, движение по рёбрам, возвраты рекурсии — на кадрах `kind="graph"` с полной топологией и обоими представлениями.

**Blocked by:** 45 (нужны модель графа, список смежности и преобразования).

**Status:** draft — ожидает утверждения на Ч2

Спека: `docs/SPEC.md`, модуль «Основы графов: представления, DFS, BFS и циклы».

`автор-черновик: человек` — пользователь пишет черновик рекурсивного DFS и его типизированных событий в `algorithms/graphs` и явно подтверждает его на Ч2.5; до этого реализация тикета не начинается. Учебная документация `docs/algorithms/` (DFS) добавляется после подтверждения черновика и до завершения тикета.

## Acceptance Criteria

- [ ] В `algorithms/graphs` есть рекурсивный DFS поверх списка смежности: старт от выбранной вершины, возврат порядка посещения достижимых вершин (недостижимые не входят); соседи перебираются в порядке возрастания номеров. Для матрицы DFS не реализуется.
- [ ] Quiet mode даёт тот же результат без событий; с Emitter типизированные события показывают вход в вершину, движение по ребру, выход из вершины (finish), текущий путь рекурсии и состояние visited — достаточно, чтобы Frame Renderer строил кадры, не зная внутренностей (ADR-0001).
- [ ] Установлен один маршрут запуска графов с семейством режимов и входом: число вершин, список рёбер (по одному `u v` на строку), выбор directed/undirected, режим (в этом тикете — dfs), стартовая вершина; точные имена маршрута и полей фиксируются этим тикетом. Дубликаты рёбер, индексы вне диапазона и неверный старт отвергаются до Run.
- [ ] Лимиты визуального Run проверяются до SSE: не более 20 вершин и не более 100 рёбер; это safety bounds визуализации, библиотека лимитов не имеет. Сервер и фронтенд зеркально валидируют ввод и лимиты до начала SSE.
- [ ] Новый `kind="graph"` — полный самодостаточный снимок (ADR-0002): вся топология (вершины `0..n-1`, рёбра, флаг directed/undirected), оба представления (список и матрица) видны в кадре, позиции вершин детерминированы (круговая раскладка), изолированные вершины и несвязные графы рендерятся; есть активная вершина/путь рекурсии, посещённые вершины с порядком, состояние режима и пояснение на русском. Запуск начинается с исходного кадра, далее кадр на событие; верхняя граница потока кадров при выбранных типах событий зафиксирована в тикете.
- [ ] Фронтенд позволяет ввести граф и старт, зеркально проверяет ввод и лимиты, строит URL запуска и рендерит `kind="graph"`; существующие визуализации, `kind="tree"`, общий SSE-транспорт и плеер не меняются.
- [ ] Тесты на швах: публичный API (quiet + emitter-шпион на известном графе: порядок посещения, вход/ребро/выход, путь рекурсии, visited; несвязный граф, изолированная стартовая вершина, старт из вершины без рёбер); SSE-интеграция (известный граф → последовательность кадров, ошибки ввода и лимитов до SSE); фронтенд (разбор ввода, URL, зеркальная валидация, рендер графа с изолированной вершиной; DOM ниже публичного renderer-интерфейса и `fetch` без инъекции не тестируются).
- [ ] `go build ./...`, `go vet ./...`, `go test ./...` и `golangci-lint run ./...` проходят; для фронтенда `pnpm install --frozen-lockfile` + lint/test/build проходят.
- [ ] Имплементор не меняет `PROGRESS.md`.
