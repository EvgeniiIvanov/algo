# 47: Графы — BFS: порядок обхода, расстояния и кратчайший путь

**What to build:** учащийся запускает BFS от выбранной вершины, видит порядок обхода достижимых вершин и расстояния, и восстанавливает один кратчайший путь до выбранной цели; недостижимая цель — нормальный результат «пути нет».

**Blocked by:** 46 (нужны модель графа, маршрут и рендерер `kind="graph"`).

**Status:** approved (Ч2)

Спека: `docs/SPEC.md`, модуль «Основы графов: представления, DFS, BFS и циклы».

`автор-черновик: человек` — пользователь пишет черновик BFS, расстояний и восстановления кратчайшего пути в `algorithms/graphs` и явно подтверждает его на Ч2.5; до этого реализация тикета не начинается. Учебная документация `docs/algorithms/` (BFS) добавляется после подтверждения черновика и до завершения тикета.

## Acceptance Criteria

- [ ] В `algorithms/graphs` есть BFS поверх списка смежности: старт от выбранной вершины, возврат порядка обхода достижимых вершин и расстояний; соседи перебираются в порядке возрастания номеров. Вершина помечается visited при постановке в очередь, поэтому каждая вершина попадает в очередь один раз. Для матрицы BFS не реализуется.
- [ ] Поддерживается восстановление одного кратчайшего пути до выбранной целевой вершины (по предкам); в невзвешенном графе длина пути равна расстоянию BFS. Недостижимая цель — нормальный результат «пути нет», не ошибка входа; цель, равная старту, даёт путь из одной вершины.
- [ ] Quiet mode и типизированные события дают одинаковое поведение; гранулярность по спеке: не более одного события постановки в очередь (несёт отметку visited и расстояние) и одного события извлечения на каждую достижимую вершину и не более одного события на каждую проверку элемента списка смежности — достаточно для кадров очереди/расстояний/visited и верхней границы потока 2V + 2E + 2 кадров (ADR-0001).
- [ ] Существующий маршрут `GET /api/run/graph` расширяется режимом `bfs` (вход добавляет необязательный query-параметр `target` — только для `bfs`); новых имён режимов нет, отдельного режима `bfs-path` нет: `bfs` всегда возвращает порядок обхода и расстояния и опционально — один кратчайший путь, когда задан `target`. Предыдущий режим `dfs` не ломается. Плохие, отсутствующие или вне-диапазона query-параметры по контракту тикета 46 — `target` в `dfs`/`cycles`, отсутствие `start` или вне диапазона для `bfs`, `start`/`target` в `cycles`, нецелые или вне диапазона `u v`, дубликаты рёбер — отвергаются до Run.
- [ ] Лимиты визуального Run — вершины в диапазоне 0..20 и не более 100 рёбер — зеркально проверяются сервером и фронтендом до SSE; библиотека лимитов не имеет.
- [ ] Кадры `kind="graph"` сохраняют полный снимок топологии и оба представления и дополняются состоянием BFS: очередь, visited, расстояния, активное ребро/вершина, восстановленный путь; пояснения на русском. `kind="tree"`, общий SSE-транспорт и плеер не меняются.
- [ ] Тесты на швах: публичный API (порядок и расстояния на связном, несвязном графе и графе с изолированными вершинами; недостижимая цель как «пути нет»; старт = цель; петля не ломает обход; единственность постановки в очередь по emitter-шпиону); SSE-интеграция (запрос `/api/run/graph` в режиме `bfs` на известном графе → кадры BFS и пути, включая случай без `target` и недостижимую цель, ошибки до SSE); фронтенд (ввод цели, зеркальная валидация, рендер очереди/расстояний/пути; DOM ниже публичного renderer-интерфейса и `fetch` без инъекции не тестируются).
- [ ] `go build ./...`, `go vet ./...`, `go test ./...` и `golangci-lint run ./...` проходят; для фронтенда `pnpm install --frozen-lockfile` + lint/test/build проходят.
- [ ] Имплементор не меняет `PROGRESS.md`.
