# 48: Графы — обнаружение циклов (directed и undirected)

**What to build:** учащийся запускает режим `cycles` на направленном и неориентированном графе и видит первое найденное цикличное ребро; на несвязном графе алгоритм сканирует каждую компоненту и находит цикл и в компоненте, просматриваемой после первой компоненты при переборе корней по возрастанию ID. Пользовательский старт не принимается. Отдельного разбора графа на компоненты и режима components нет — только сканирование циклов по всем компонентам.

**Blocked by:** 46 (нужны модель графа, маршрут и рендерер `kind="graph"`; от 45 — список смежности).

**Status:** approved (Ч2)

Спека: `docs/SPEC.md`, модуль «Основы графов: представления, DFS, BFS и циклы».

`автор-черновик: человек` — пользователь пишет черновик обнаружения циклов (white/gray/black и visited+parent) в `algorithms/graphs` и явно подтверждает его на Ч2.5; до этого реализация тикета не начинается. Учебная документация `docs/algorithms/` (циклы) добавляется после подтверждения черновика и до завершения тикета.

## Acceptance Criteria

- [ ] В `algorithms/graphs` есть обнаружение циклов поверх списка смежности, останавливающееся на первом свидетеле цикла. Directed — цветовая схема white/gray/black: свидетель — обратное ребро (back edge) в серую вершину. Undirected — visited+parent: свидетель — ребро к уже посещённой вершине, не являющейся родителем; ребро к родителю циклом не считается. Петля (self-loop) — цикл в обоих режимах. Найденный свидетель возвращается как результат (вершины/ребро); отсутствие циклов — нормальный результат, не ошибка. Для матрицы алгоритм не реализуется.
- [ ] Сканирование обязано покрыть каждую компоненту несвязного графа: корни перебираются по возрастанию номеров вершин, и алгоритм находит цикл в компоненте, просматриваемой после первой компоненты при переборе корней, если ранее просмотренные компоненты ацикличны. Отдельного API разметки компонент, возврата меток компонент и визуального режима components нет — это out of scope (см. спеку).
- [ ] Quiet mode и типизированные события дают одинаковое поведение; гранулярность по спеке: вход/переход цвета и выход/переход цвета на каждую достигнутую вершину, не более одного события на каждую проверку элемента списка смежности и не более одного итогового события результата (свидетель или «циклов нет») — достаточно для кадров раскраски/свидетеля и верхней границы потока 2V + 2E + 2 кадров (ADR-0001).
- [ ] Существующий маршрут `GET /api/run/graph` расширяется режимом `cycles` для directed/undirected; предыдущие режимы (`dfs`, `bfs`) не ломаются; новых имён режимов нет. Для `cycles` поля `start` и `target` не принимаются: сканирование начинается с непосещённых корней в порядке возрастания номеров вершин. Плохие, отсутствующие или вне-диапазона query-параметры по контракту тикета 46 (неизвестный `mode`, нецелое или вне 0..20 `vertices`, `directed` не `true`/`false`, заданные `start`/`target` в `cycles`, нецелые или вне диапазона `u v`, дубликаты рёбер) и превышение лимитов отвергаются до Run.
- [ ] Лимиты визуального Run — вершины в диапазоне 0..20 и не более 100 рёбер — зеркально проверяются сервером и фронтендом до SSE; библиотека лимитов не имеет. `cycles` на пустом графе (0 вершин) — валидный Run с результатом «циклов нет».
- [ ] Кадры `kind="graph"` сохраняют полный снимок топологии и оба представления и дополняются состоянием поиска циклов: раскраска вершин, активное ребро, подсветка найденного цикличного ребра; пояснения на русском. `kind="tree"`, общий SSE-транспорт и плеер не меняются.
- [ ] Тесты на швах: публичный API (directed: цикл и нет циклов, цикл через несколько рёбер, свидетель — обратное ребро в серую вершину; undirected: ребро к родителю — не цикл, ребро к не-родителю — цикл; петля — цикл в обоих режимах; цикл в компоненте, просматриваемой после первой компоненты при переборе корней по возрастанию ID, находится сканированием всех компонент; детерминированная остановка на первом свидетеле; отсутствие циклов в графе с несколькими ациклическими компонентами; emitter-шпион на известной последовательности); SSE-интеграция (запрос `/api/run/graph` в режиме `cycles` на известных графах → кадры, ошибки до SSE); фронтенд (выбор режима, зеркальная валидация, рендер раскраски/свидетеля; DOM ниже публичного renderer-интерфейса и `fetch` без инъекции не тестируются).
- [ ] `go build ./...`, `go vet ./...`, `go test ./...` и `golangci-lint run ./...` проходят; для фронтенда `pnpm install --frozen-lockfile` + lint/test/build проходят.
- [ ] Имплементор не меняет `PROGRESS.md`.
